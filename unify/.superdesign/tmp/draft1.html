The Problem

Dataset 01

C-MAPSS

  • 21 Sensors
  • Time: Cycles
  • Object: Turbofan
Dataset 02

FEMTO/PRONOSTIA

  • 15/16 Sensors
  • Time: Seconds
  • Object: Bearing
Dataset 03

XJTU-SY

  • 15/16 Sensors
  • Time: Minutes
  • Object: Bearing

A fixed input width forces one model per dataset, preventing shared learning across diverse telemetry sources. Furthermore, mixing raw time units lets whichever dataset has the largest absolute numbers dominate the loss function, destroying convergence on the others.

UNIFY-RUL solves this via architecture and target normalization. The model predicts a normalised fraction of life in [0,1], which is then denormalised back to the native domain (cycles, seconds, or minutes) using a per-dataset life_scale.

Efficiency Observation

One core is enough — going from 1 thread to 4 buys 0.12 ms on a path where the 1-second feature window costs 1000 ms.

Stability Observation

The tail is flat — p99 is 5 percent above p50, because a 44k-parameter model fits in cache and does not thrash.

What this is not

Four things this project does not claim

Qualitative Constraint

FEMTO and XJTU are not downloaded — the three-dataset universality claim is demonstrated on C-MAPSS and synthetic data, not on all three.

Statistical Limitation

The live rig has no ground-truth RUL — you cannot run a bearing to destruction in a semester, and one bearing death is one sample.

Sensor Fidelity

The MPU-6050 tops out at 1 kHz against the bearing datasets 25.6 kHz — it cannot see the resonances a spall excites.

Domain Gap

The Pi runs the synthetic build, not the C-MAPSS model whose accuracy is reported above — a turbofan-trained model fed vibration features would return a number with no meaning.

Reproduce it

The entire stack runs on generated run-to-failure data. No downloads, about five minutes.

python -m venv .venv
source .venv/bin/activate
pip install -r requirements-train.txt
